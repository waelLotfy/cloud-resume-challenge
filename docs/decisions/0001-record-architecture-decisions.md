# 1. Record Architecture Decisions

## Status

Proposed

## Context

We need a record of the architectural decisions made on this project,
including the rationale, so that future contributors understand why the
system is shaped the way it is (e.g. three-tier serverless design, no
VPC, Terraform as the sole IaC tool, GitHub Actions with OIDC for CI/CD).

## Decision

We will use Architecture Decision Records, as described by Michael
Nygard, to capture significant architectural decisions along with their
context and consequences. Each ADR is numbered sequentially and stored in
`docs/decisions/`.

## Consequences

See [`docs/decisions/README.md`](./README.md) for the process of adding
new ADRs.
